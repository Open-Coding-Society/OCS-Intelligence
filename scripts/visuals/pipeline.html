From a student's editor to a GPU

Students call one public URL, https://ai.opencodingsociety.com/v1. EC2 is the only machine on the internet: it checks the key, holds each request in a per-model wait line, and passes it over the private NetBird network to the GPU rigs in the school.

One Copilot request, step by step

  1. Copilot sends POST /v1/chat/completions with the student key and a model name, over HTTPS to ai.opencodingsociety.com.
  2. Nginx on EC2 ends TLS and hands every /v1/ path to the gateway on localhost.
  3. The gateway checks the key (wrong key: 401), then puts the request in that model's wait line. A full line answers 429 with Retry-After: 15.
  4. When a GPU slot frees up, the gateway forwards the request over NetBird to Rig 1's orchestrator on TCP 9000.
  5. The orchestrator picks Worker A or B by the model name and swaps the student key for the worker's secret.
  6. llama-server runs the model across its four GTX 1070s and streams tokens back through every hop to the editor.

Rules are one-way: replies flow back, but nothing can open a connection to an operator laptop, and the rigs can't open one to EC2. The rig-to-rig rule exists so Open WebUI on Rig 1 can reach Rig 2. It's temporary, until a router sits between the rigs.
